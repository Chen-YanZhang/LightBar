状态灯颜色

板上 RGB 指示灯

指示灯每秒刷新一次,反映安全状态机的当前状态。闪烁的颜色优先级高于常亮。

  • 白色 常亮正常运行:输出门禁打开,灯光按设定输出。
  • 白色 闪烁正在运行,但至少一串 LED 被驱动判定开路/短路并关闭,或一颗驱动卡在故障恢复循环(该路不亮)。概览页会标出是哪一串。重新接好后需要断电重启(本板)或点「重新检测灯串」(新板)。
  • 蓝色 闪烁Matter 配对窗口打开(可以在 Home Assistant 里添加设备)。优先级最高,会覆盖其它颜色。
  • 暗青色 常亮启动中,或输出已停止但驱动芯片在线(例如刚上电、门禁尚未打开)。
  • 琥珀色 常亮上电时驱动报告 CRCERR(出厂配置加载失败),门禁锁定。只有彻底断电再上电才能清除。
  • 红色 闪烁驱动正在报告严重故障(输入过压/欠压、boost 过流/过压、电荷泵、配置电阻缺失、热关断等),输出已被切断。故障消失后 1 秒内自动恢复。
  • 紫色 闪烁板温超过保护阈值(默认 80 °C),两颗驱动输出被强制关闭;降到 68 °C 以下并持续 3 秒后自动恢复。
  • 洋红色 常亮两颗 TPS92390 都没有应答 I2C:驱动未供电、总线故障或硬件损坏。

HTTP API

—

本页面没有任何后台服务,所有数据都来自设备自带的 HTTP 服务器(端口 80,无鉴权,仅限局域网)。页面读状态的方式:每 2 秒 GET /api/status 刷新概览;进入「高级」时再 GET /api/diag 与 /api/log;配网页每 2 秒 GET /api/prov。控件改动经 POST 发出,表单编码 application/x-www-form-urlencoded,响应均为 JSON。你可以用 curl / Home Assistant RESTful / 任何脚本直接调用。

方法路径参数说明
GET/api/status—运行状态(页面主数据源):version, state, gate, temp, light{on,level,mireds}, auto, fsm[2], driver, level_cap, current_code, chips_ack, ip, commissioned, led_brightness, uptime, strings{n, warm{fault,kind}, cold{fault,kind}}, reprobe, rev, hw{warm/cold: mode, strings, boost_khz, pwm_hz, invstring}(芯片 1Eh 自检), diag{on,warm,cold}, chips[{fsm,stuck,want}](stuck = 该路要亮却 ≥3 s 未进 NORMAL)
GET/api/diag—两颗 TPS92390 寄存器 00/02/0E/10/12/14/16/18/1A/1C/1E、堆、RSSI、boots、crit_events、tune、最近 8 条故障历史
GET/api/log—本次开机以来的事件环(64 条):wifi / matter / light / sm / ota / web / cli
GET/api/prov—配网状态、热点 SSID、IP、Matter 手动配对码与 QR 载荷
GET/api/scanstart=1 启动扫描附近 Wi-Fi 列表(异步,轮询直到 scanning=0)
POST/api/lighton=0|1 level=1-254 mireds=200-370设灯。任一参数可省略:缺 on 保持开关、缺 mireds 保持色温(自适应时页面就这样发)
POST/api/autoon=0|1(省略 = 切换)日光自适应色温开关
POST/api/diagdriveon=0|1 warm=0-100 cold=0-100诊断模式:绕过色温混光,按百分比独立驱动两颗芯片;易失,不持久化
POST/api/strings/reprobe—EN 断电重启驱动以重新启用已接好的灯串(新板);本板返回 ok=0 并提示断电
POST/api/curlevel=0x10-0xF0(8 位,电流码 = level×16)每串 LED 电流上限,夹到额定 0xF0 = 150 mA,持久化
POST/api/caplevel=8-254亮度上限,持久化
POST/api/tuneslope=0-7 dither=0-4 ss_range=0-3 ss_mod=0-3 ss_pseudo=0|1驱动参数(任一子集):过渡时间/抖动/芯片扩频,即时写两颗芯片并持久化;ss_* 仅在 rev=PCB3_3(BST_SYNC 接高)上有效
POST/api/ledbrightness=0-255状态灯亮度,持久化
POST/api/provssid= pass=加入 Wi-Fi(经 Matter 网络驱动写入,异步)
POST/update原始 .bin 字节流OTA 写入备用分区并重启;新镜像自检失败自动回滚
POST/api/factory_resetconfirm=yes清除 Matter fabric / Wi-Fi / 亮度上限 / 驱动参数 / 灯光记忆,重启进配网热点

示例:curl -s http://设备IP/api/status curl -X POST -d "on=1&level=180&mireds=300" http://设备IP/api/light
